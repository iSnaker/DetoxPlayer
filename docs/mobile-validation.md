# Проверка мобильных функций

Новые функции от 29 октября 2026. Автоматические проверки: 33 Flutter-теста,
анализатор без замечаний, Android debug APK собирается. Сценарии ниже ещё
не проверены на реальных устройствах в этой работе.

## Где находятся функции

- Меню трека: «Скачать для офлайн», «Добавить в плейлист».
- Страница альбома: **Играть → Добавить в плейлист → Перемешать → Скачать**.
  На узком экране кнопки переносятся на следующую строку.
- «Плейлисты»: + создаёт плейлист; на его странице доступны переименование,
  удаление, проигрывание и скачивание. Кнопка минус удаляет запись из плейлиста.
- «Настройки → Скачанная музыка»: проигрывание готовых файлов, статусы,
  пауза/продолжение, отмена, повтор и удаление с устройства.
- «Настройки → Журнал диагностики»: просмотр, копирование, экспорт JSON,
  очистка. Журнал ограничен 800 событиями; время в UTC. Ключи и URL скрыты.
  Название транспорта сети не доказывает доступность интернета.

## Сценарии на Android и iPhone

| Сценарий | Ожидаемый результат |
| --- | --- |
| Скачать трек и альбом, повторить действие | Видны статусы и отметка скачивания; дубли не создаются. |
| Включить авиарежим, перезапустить приложение, открыть скачанное | Готовые треки играют, перематываются и переключаются без сервера. |
| Добавить трек и тот же альбом в плейлист | Каждый ID добавлен один раз, порядок добавления сохранён. |
| Переименовать плейлист, перезапустить, удалить запись/плейлист | Изменения сохранены; скачанные файлы остаются. |
| Удалить трек из серверного каталога и обновить клиент | Запись плейлиста сохранена; без локальной копии недоступна, с копией играет. |
| Скачать большой альбом, свернуть приложение/заблокировать экран | Системная загрузка продолжает работу в рамках ограничений ОС; после открытия статусы сверяются. |
| Потерять сеть при скачивании, восстановить, нажать паузу/продолжить | Задание возобновляется; при невозможности resume можно повторить загрузку. Частичный файл не проигрывается. |
| Отменить загрузку, повторить; удалить готовый файл | Отмена не превращается поздним событием в готовый трек; повтор создаёт новое задание, удаление освобождает место. |
| Мало свободного места | Загрузка останавливается с ошибкой; файл не помечается готовым. |
| Отозвать тестовый ключ при загрузке | Новые запросы отклоняются; уже скачанные треки остаются доступны. |
| Переключать Wi-Fi ↔ мобильная сеть при проигрывании | Проверить продолжение; при ошибке «Повторить» открывает источник заново с прежней позиции. |
| Слушать более 15 треков, использовать экран блокировки/гарнитуру | Правильный текущий трек, переходы, shuffle/repeat и отсутствие роста окна источников. |

ОС определяет время фоновой передачи. На iOS после принудительного закрытия
приложения может потребоваться повторное открытие. Проверку исключения из backup
провести на iOS отдельно; в коде включён `Config.excludeFromCloudBackup`.
Плейлисты и скачанное локальны для устройства и адреса сервера, между телефонами
не синхронизируются. Обложки пока загружаются отдельно по сети; при их отсутствии
показывается стандартная иконка, аудио остаётся доступным.

## Если воспроизведение снова остановится

1. Запомнить приблизительное время, действие и сеть (Wi-Fi/мобильная).
2. Открыть «Настройки → Журнал диагностики» и экспортировать журнал.
3. Нажать «Повторить» в плеере и отметить, помогло ли это.
4. Сохранить модель телефона, версию ОС и сведения о блокировке экрана/фоне.

Журнал включает native-код/индекс ошибки, позицию и буфер, события загрузки,
смену сети и жизненного цикла. HEAD после ошибки — отдельный запрос диагностики,
а не точный HTTP-ответ исходного потока. Корневая причина ранее наблюдавшегося
сбоя пока не подтверждена.

## Сборка

Android: из `app` выполнить `flutter pub get`, `flutter build apk --debug`.
APK: `app/build/app/outputs/flutter-apk/app-debug.apk`.

На Mac после получения изменений выполнить из `app` `flutter pub get`, затем
`flutter build ios --debug --no-codesign` для проверки компиляции. Для установки
открыть `ios/Runner.xcworkspace` в Xcode, выбрать свою команду подписи и iPhone.
Новые зависимости требуют разрешения CocoaPods при iOS-сборке. Podfile.lock
на Windows не обновлялся; результат Xcode и аппаратные проверки нужно записать.
