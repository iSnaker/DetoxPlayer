# Запуск на Windows

## Первый запуск

Нужны Git и Docker Desktop в режиме Linux containers (WSL 2 backend). Диск с музыкой должен быть доступен Docker Desktop. Команды выполняются в PowerShell.

```powershell
git clone https://github.com/iSnaker/DetoxPlayer.git
cd DetoxPlayer
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
```

В `.env` уже указан `MUSIC_PATH=F:/Music`. Если путь отличается, исправьте его до запуска. Несуществующая папка не создаётся автоматически: запуск вернёт ошибку монтирования. Если порт 8080 занят, измените `ADMIN_PORT`.

После запуска контейнера получите административный секрет:

```powershell
docker compose exec server python -m app.secret
```

Откройте http://localhost:8080 и введите секрет. Он создан автоматически и сохраняется в томе `library-data`. Административный секрет даёт доступ к управлению сервером, а ключи устройств предназначены для будущих клиентов плеера. Секрет не выводится в логи сервера.

Нажмите «Добавить папку», откройте `/sources/music`, задайте название и нажмите «Добавить и сканировать». Можно добавить весь подключённый каталог или несколько непересекающихся вложенных папок. `F:/Music` на Windows соответствует `/sources/music` внутри контейнера.

Музыка индексируется на месте; копирования 60 ГБ в Docker нет. В первой реализации индексируются MP3, включая файлы с расширением `.MP3`. Теги извлекаются из MP3, для отсутствующих тегов используются имя файла и заглушки. Неподдерживаемые форматы пропускаются. Повреждённые MP3 отображаются с предупреждением; они не останавливают весь обход.

## Дополнительные каталоги и диски

Контейнер видит только папки, явно подключённые в Compose. Панель позволяет выбирать их и вложенные папки; стандартный браузерный выбор файлов не предоставляет серверу доступ к Windows-дискам.

Например, чтобы подключить `G:/Archive`, создайте рядом с `compose.yaml` файл `compose.override.yaml`:

```yaml
services:
  server:
    environment:
      SOURCE_ROOTS: /sources/music;/sources/archive
    volumes:
      - type: bind
        source: G:/Archive
        target: /sources/archive
        read_only: true
        bind:
          create_host_path: false
```

Затем:

```powershell
docker compose up -d
```

Compose автоматически объединит основной файл и override. Каталог `/sources/archive` появится при добавлении папки в панели. База, секрет и ключи сохранятся. Локальные пути в `.env` и `compose.override.yaml` не загружаются в Git.

Для нового источника внутри уже подключённой папки менять Compose не требуется. Папки, которые пересекаются с добавленными источниками, не принимаются: сначала уберите родительский источник, если хотите разделить его на вложенные.

## Работа с библиотекой

- Поиск — по названию, исполнителю, альбому, имени файла, пути и названию источника, с учётом русского регистра. Можно выбрать источник и папку, использовать страницы по 50 треков.
- «Пересканировать» — учитывает новые, изменённые и удалённые файлы. ID ранее известных треков по тому же пути сохраняются. Перемещение или переименование файла пока создаёт новую запись.
- «Сбросить индекс и пересканировать» — заново читает все MP3 и атомарно обновляет каталог после успешного обхода всех источников. Ключи, папки и файлы сохраняются. Известные ID по прежним путям также сохраняются. При недоступной папке полный сброс не применяется; прежний каталог остаётся доступным.
- «Убрать» — исключает источник из библиотеки, файлы на диске сохраняются. Сканирование удалённого источника прекращается, его результаты не возвращают записи в каталог. Повторное добавление такого источника создаёт новые ID.
- Состояние и ошибки обновляются автоматически. Если диск временно недоступен, прежние записи сохраняются; панель показывает проблему. Сканирование одновременно выполняется одно, добавление папок во время него недоступно.
- «Выдать ключ» — показывает новый ключ один раз. В базе хранится его SHA-256 хеш. Список позволяет отозвать ключ. На этом этапе API подключения и воспроизведения для этих ключей ещё нет.

## Обновление и остановка

```powershell
git pull
docker compose up -d --build
```

```powershell
docker compose logs --tail 100 server
docker compose stop
```

`docker compose down` удаляет контейнеры, сохраняя том. `docker compose down -v` удалит базу, список источников, ключи и административный секрет — для обычного обновления эта команда не нужна. Музыкальные папки на хосте команда не удаляет.

Сессии панели живут до 12 часов или до перезапуска сервера. После перезапуска войдите с тем же административным секретом. Прерванное сканирование отмечается в панели; повторно запустите его вручную.

## Доступ

Админка публикуется исключительно на `127.0.0.1`. Для этого этапа проброс портов и домен не нужны. Публичный API, HTTPS, клиенты, обложки и воспроизведение будут добавляться следующим этапом. При этом локальную панель не нужно открывать в интернет.

## Резервная копия каталога

Для согласованной копии остановите сервер, скопируйте содержимое его named volume `library-data` стандартными средствами Docker и запустите сервер снова. В копию входят секрет и хеши ключей, поэтому храните её приватно. Музыкальные папки резервируются отдельно.
