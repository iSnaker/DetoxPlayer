# Roadmap: фактическое состояние

Обновлено 29 октября 2026. Основа — `c8fe23d` (`main`) плюс локальные изменения
плейлистов, офлайн-загрузок и диагностики. Наличие кода и проверки на устройствах
отмечены отдельно. Требования: [architecture.md](architecture.md).

## Реализовано

| Область | Состояние |
| --- | --- |
| Сервер и админка | Несколько источников, индексирование MP3, поиск, пересканирование, атомарный сброс, ключи и отзыв. [Windows-проверка](windows-validation.md). |
| Клиентский API | Bearer, cookie-сессии, каталог, Range/HEAD, обложки, version/export. |
| Мобильный Flutter | Подключение, secure storage, каталог, поиск, альбомы, исполнители, локальный кэш метаданных. Альбомы учитывают `source_id`. |
| Воспроизведение | Очередь, shuffle/repeat, перемотка, сохранение состояния, JustAudioBackground. Окно источников ограничено; после ошибки доступна повторная загрузка с сохранением позиции. |
| Локальные плейлисты | Создание, переименование, удаление; добавление трека и альбома, удаление записей, защита от дублей. Метаданные недоступных треков сохраняются. Хранилище разделено по серверу; синхронизации между устройствами нет. |
| Мобильный офлайн | Скачивание трека/альбома/плейлиста; экран загрузок, пауза/продолжение, отмена, повтор, удаление. Временные файлы проверяются по размеру и заголовку MP3; готовая копия имеет приоритет при загрузке источника плеера. |
| Фоновые загрузки | `background_downloader`: системные Android/iOS задачи, сохранение заданий, сверка после запуска, контроль свободного места, исключение файлов iOS из cloud backup. Нативный фон требует проверки на устройствах. |
| Диагностика | Ограниченный постоянный журнал: ошибки плеера, буфер/позиция, состояние приложения, транспорт сети, HTTP-результаты и HEAD-проверка после ошибки. Просмотр, копирование, экспорт и очистка в настройках. Ключи и URL скрываются. |
| HTTPS | Caddy/DuckDNS, отдельная публикация клиентского API: [инструкция](external-access.md). |

Отзыв ключа больше не вызывает автоматический выход из приложения: скачанная
музыка остаётся доступна. Явный выход отменяет незавершённые загрузки и удаляет
ключ из secure storage; локальные файлы и плейлисты сохраняются для того же сервера.

## Проверено в текущей работе

- `flutter analyze --no-pub`: без замечаний.
- `flutter test --no-pub`: **33 теста**. Включают повреждённые/частичные загрузки,
  отмену и запоздалые события, восстановление фонового завершения, плейлисты,
  редактирование журнала для скрытия секретов, повтор после ошибки плеера,
  приоритет локального файла, ограничение окна и интерфейс альбома на ширине 320 px.
- `flutter build apk --debug --no-pub`: Android APK собран; нативные Android-плагины
  скомпилированы. Ключи из локального файла настроек в сборку не включались.
- Сервер и музыкальные файлы в этой работе не изменялись.

Тесты плеера и загрузок используют подменённые системные адаптеры. Они проверяют
логику приложения, но не подтверждают поведение реальных AudioPlayer, URLSession,
WorkManager, режимов энергосбережения или аппаратных media-кнопок.

Ранее на Android PRA-TL10 проверялись публичный HTTPS, каталог, поиск,
воспроизведение, перемотка, фон, уведомления, экран блокировки, очередь и режимы.
Новые функции ещё требуют проверки на Android/iPhone. iOS-сборка на Windows
не выполнялась; существующие результаты разработки пользователя на Mac
не следует считать отсутствующими только потому, что они не записаны здесь.

## Следующие шаги

1. Проверить новые функции на телефонах по [сценариям](mobile-validation.md).
   При повторе уличной ошибки экспортировать журнал до очистки/повторных тестов.
   Причина исходной ошибки пока не установлена.
2. Проверить системные next/previous/repeat на границах окна, гарнитуру,
   звонки/аудиофокус, Huawei battery optimization и восстановление приложения.
3. Web: заменить `dart:io`-хранилища, реализовать cookie-auth, same-origin UI/API
   и браузерное воспроизведение. Наличие `app/web` не означает готовность web.
4. Android Auto: автомобильная декларация, дерево каталога и проверки.
   CarPlay: entitlement, нативная scene/template-интеграция и устройства.
5. Выпуск: release signing (сейчас Android debug signing), подключение иконок,
   воспроизводимая инструкция Mac/iPhone и результаты проверок внешней сети.

Этапы: **1 — реализован; 2 — мобильный прототип есть, проверки устройств
продолжаются; 3 — очередь, плейлисты и офлайн реализованы, требуется нативная
проверка; 4 — HTTPS готов, web/автомобильные интерфейсы/выпуск остаются.**
