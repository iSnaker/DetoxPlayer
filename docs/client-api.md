# Клиентский API v1

Локальный адрес: `http://localhost:8081`. Админка остаётся на порту 8080.
API — отдельное ASGI-приложение `app.client:create_app`; маршрутов `/admin/*`
в нём нет. Серверный каталог и выдача аудио готовы, Flutter UI пока отсутствует.

## Авторизация

Создайте ключ устройства в локальной админке. Мобильные клиенты передают его
в `Authorization: Bearer <ключ>` при **каждом** запросе, включая обложки,
HEAD, перемотку и возобновление загрузки. Ключи в query string не принимаются.
Административный секрет и cookie `detox_admin` не авторизуют клиентский API.

Ключи и web-сессии хранятся как SHA-256 хеши. Отзыв ключа блокирует новые
запросы и удаляет его web-сессии. Уже авторизованный поток может завершиться;
скачанные файлы сохраняются на устройстве. Отмена запроса закрывает файловый
дескриптор и прекращает чтение. Access log Uvicorn отключён у обоих сервисов.

`401` — отсутствующий, истёкший или отозванный ключ/сеанс; `429` — слишком
много неудачных попыток (`Retry-After: 60`). Лимит одного процесса: 20 неудач
за минуту с адреса клиента и 300 суммарно. За reverse proxy без настройки
доверия все клиенты будут иметь его адрес; внешнее развёртывание требует
отдельной настройки HTTPS и trusted proxy. Сейчас proxy headers отключены.

### Web-сессия

`POST /api/v1/session` с Bearer-ключом и `X-Detox-Client: 1` создаёт cookie
`detox_client` с `HttpOnly`, `SameSite=Strict`, `Path=/api/v1`, сроком 30 дней.
При HTTPS устанавливается `Secure`; локальная HTTP-разработка работает без
него. В ответе — устройство и `expires_at` (Unix seconds), сам токен не
возвращается. Сессия переживает перезапуск API, но проверяет отзыв ключа на
каждом запросе. На ключ сохраняются последние 10 сессий.

Браузер должен работать на том же origin, что и API. CORS не включён.
`<audio src="/api/v1/tracks/ID/audio">` и `<img>` получают cookie автоматически.
Ключ не нужно класть в URL или localStorage. `DELETE /api/v1/session` с
`X-Detox-Client: 1` завершает текущую сессию. Для обеих мутаций проверяются
Origin (если есть) и Fetch Metadata; чужой origin отклоняется с `403`.

## Маршруты

Все маршруты ниже, кроме `/health`, требуют ключ или web-сессию.

| Метод и путь | Результат |
| --- | --- |
| `GET /health` | `{"status":"ok"}` |
| `GET /api/v1/me` | `device: {id, name}`, `api_version: 1` |
| `GET /api/v1/sources` | `items`: ID, имя, число треков и доступность; без серверных путей |
| `GET /api/v1/tracks` | Каталог с `q`, `source_id`, `folder`, `offset`, `limit` |
| `GET /api/v1/folders` | Папки с `source_id`, `offset`, `limit` |
| `GET /api/v1/library/version` | `{version, total}`: дешёвая проверка, изменилась ли медиатека |
| `GET /api/v1/library/export` | Вся медиатека одним JSON `{version, total, items}`; при `Accept-Encoding: gzip` ответ сжат |
| `GET /api/v1/tracks/{id}` | Один доступный трек |
| `GET`, `HEAD /api/v1/tracks/{id}/audio` | MP3, `audio/mpeg`, Range и валидаторы |
| `GET`, `HEAD /api/v1/tracks/{id}/cover` | JPEG до 512×512 или заглушка |

Каталог возвращает `total`, `offset`, `limit`, `items`. По умолчанию 50 треков,
максимум 200; для папок — 100 и 500. Поиск регистронезависимый, включая русский.
`folder` — точный относительный путь, `.` — корень источника. Отдельные поля
трека: `id`, `source_id`, `source_name`, `path`, `folder`, `filename`, `title`,
`artist`, `album`, `duration` (секунды или null), `size`, `error`, `audio_url`,
`cover_url`. Все пути относительные, URL без ключей.

При временно недоступном диске каталог остаётся виден, источник имеет
`available: false`; чтение файла возвращает `404`. Удалённые источники и
недоступные записи исключены из выдачи. ID файла разрешается через БД с
проверкой границ источника после разрешения symlink; пути от клиента не
принимаются. Каждый запрос обложки также проверяет доступность трека,
даже если JPEG уже есть в кэше.

## Аудио

- Полный запрос: `200`, `Content-Length`, `Accept-Ranges: bytes`, `ETag`,
  `Last-Modified`. Аудио отдаётся порциями по 64 КиБ, без транскодирования.
- Один диапазон `bytes=0-4095`, `bytes=4096-`, `bytes=-4096`: `206` с
  `Content-Range`. Некорректный/недостижимый диапазон: `416`, `bytes */размер`.
- Несколько диапазонов или неизвестная единица игнорируются: полный `200`.
- `If-Range` сравнивается с текущим сильным ETag или точным Last-Modified;
  при несовпадении сервер отдаёт полный файл.
- `HEAD` возвращает заголовки полного файла без тела, Range игнорируется.
- `?download=true` меняет `Content-Disposition` на `attachment` с UTF-8 именем.
  Офлайн-очередь и фоновые загрузки на телефоне ещё предстоит реализовать.
- Ответы имеют `Cache-Control: private, no-store`; клиенты могут использовать
  полученные валидаторы для контролируемого возобновления загрузки.

## Обложки

Приоритет: встроенная APIC (front cover первой), `cover.jpg`, `folder.jpg`,
заглушка. При повреждённой картинке пробуется следующий вариант. JPEG
перекодируется без исходных метаданных, оригиналы не изменяются.
Лимиты входа: 16 МиБ на ID3/картинку и 20 миллионов пикселей. Производные
JPEG лежат в `library-data/covers`; кэш ограничен 6 000 файлами. Размер и
mtime MP3/файлов обложек входят в ключ кэша, поэтому изменения на диске
обновляют результат. Успешный полный сброс индекса также начинает новое
поколение кэша; старые файлы постепенно вытесняются в пределах лимита.
Неудачный сброс сохраняет прежнее поколение. Кэш не является резервной копией музыки.

## Пример PowerShell

Ключ вводится скрыто; не вставляйте его в командную строку, URL или репозиторий.

```powershell
$deviceKey = Read-Host 'Ключ устройства' -AsSecureString
$headers = @{ Authorization = 'Bearer ' + [System.Net.NetworkCredential]::new('', $deviceKey).Password }
$catalog = Invoke-RestMethod http://localhost:8081/api/v1/tracks -Headers $headers
$catalog.items | Select-Object title, artist, album
$track = $catalog.items[0]
Invoke-WebRequest ("http://localhost:8081" + $track.audio_url) -Method Head -Headers $headers
$headers.Clear()
```

Не открывайте HTTP-порт в интернет. Подключение телефона, внешний адрес,
публичный TLS и размещение Flutter web на том же origin — следующие этапы.
